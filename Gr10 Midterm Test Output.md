### **A. GROUP VERIFICATION**

**1\. Biggest issue to solve before Week 6**

Our financial logic. The Rulebook in `CALCULATIONS_AND_LOGIC_TEST.md` is built on too many team-defined assumptions (the Burden gate, the NDI-based affordability ratio, the risk-adjustment multipliers, the band widths). In real bank practice these are rarely used in this form; the main affordability test is DTI. Our rulebook is therefore not close enough to how a real credit assessment actually works.

**2\. Why this is the biggest issue**

The financial logic is the foundation of the whole product. Everything else is built on top of it: the MVP decision flow, the user flow, the answer bands, the Approve/Reduce Limit/ Reject classification, and the scoring. If the rulebook is not realistic, every downstream part inherits the same weakness, and the product can run correctly while still producing a financially unjustified result. Fixing any other part first would be wasted work, because those parts would have to be rebuilt once the logic changes.

**3\. What the team has done about it so far**

- Seek advice from banking practitioners on how personal credit affordability is assessed in practice.  
- Check our sources and disclose each threshold as either Sourced or Assumption.  
- Test our calculations by hand and built a 5-dossier answer key plus a full worked sample case.  
- Run the logic on the prototype to see the input-to-output flow end to end.

From this we identified the problem clearly and we now know the direction of the fix: reduce the assumption load and rebuild the rule around DTI as the primary measure.

**4\. What the team will do next** 

1. Revise the Rulebook so it follows the order a real bank uses, with DTI as the main affordability test, and keep only the assumptions we can justify.  
2. Re-derive the answer key for all dossiers under the revised rule and lock it as the single source of truth.  
3. Test more cases against the revised rule (normal, boundary at each threshold, and invalid inputs) and record expected versus actual results.  
4. Update the MVP, user flow and scoring to match the revised logic, so all files stay consistent.
